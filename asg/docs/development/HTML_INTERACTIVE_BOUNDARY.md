# Interactive HTML preview boundary experiment

F11 / issue #402. The base under examination is
`1a652bb21d1a2b4710fd2dad2c702e4aaa9bcd8d`. PR #513 merged the fixed
starter's Stop-before-dispatch correction at `111bd8945d73b1ffb643769c9507ea4dc6ea45d6`.
PR #514 merged fixed export authority at `b8dde039ab8bdf13a1621ed0014b099e6038a230`.
These supply passive lifecycle and export groundwork. The interactive experiment
runs outside the app. The reviewed-source host still sends an opaque-origin
CSP sandbox with `script-src 'none'`.

## Threat model

Treat every generated byte and every message from the child as attacker
controlled. A script may try to read the Studio DOM, credentials, workspace
files, preview tokens, local model APIs or other local services. It can attempt
to transmit data, persist state, navigate away, prompt the user, or keep running
after Stop. The trusted side is the preview supervisor, the immutable reviewed
snapshot, and the browser policy and isolation mechanisms explicitly controlled
by the supervisor. Browser instrumentation in this fixture is trusted test
code. It confers no authority on an application message channel.

The experiment serves fixed markup from an ephemeral loopback listener. The
candidate permits JavaScript in an iframe with `sandbox="allow-scripts"` and
also sends CSP `sandbox allow-scripts`. It denies default resource loading and
connections, form submission and base URLs. It does not grant same-origin
access. A separate ephemeral loopback origin records requests. A permissive
control runs only the same synthetic fixture in a separate throwaway profile
and deliberately enables its canary effects so a dead endpoint cannot appear
to prove isolation. Both runs disable Chrome's popup heuristic to measure the
sandbox's popup restriction. The probe accepts only an installed Chrome
executable and supplies its own fixed document bytes.

## Measured results

Chrome 156.0.8078.81 on macOS 27.0.1 arm64 produced the following observations.

| Surface | Candidate | Permissive control |
| --- | --- | --- |
| Local script | Synthetic button click changes its text to `1` | Same |
| Origin and storage | Message reports `null` origin. Parent DOM, cookies, localStorage and IndexedDB attempts throw `SecurityError`. | Parent DOM and localStorage accessible. Cookie getter returns a string and IndexedDB accepts the open call. |
| Subresources | Fetch rejects. Canary sees neither fetch nor image. | Fetch fulfills. Canary sees fetch and image. |
| Forms and popups | Canary sees neither form POST nor popup. The popup call returns null. | Canary sees form and popup. The popup call returns a window handle. |
| Top navigation | Assignment throws `SecurityError` and canary sees no request. | Omitted to preserve the host collecting results. |
| Child navigation | Assigning the child's own location reaches the canary. | Same |
| Stop | Host removes the child, sees a null `contentWindow`, and receives no late signal. The connected candidate timer did not emit a late signal within this headless observation. | The detached child sends no late signal or canary request. A separate retained child emits both. |

Child navigation is a concrete network egress path even with the proposed CSP
and sandbox. A URL can carry attacker-chosen data before the supervisor can
observe the navigation. A passing probe includes reproducing this failure. It
is a decision to reject the browser-only candidate for production interactive
preview.

The Stop experiment measures frame detachment and a finite delayed-effect
control. It cannot establish termination under CPU starvation, cleanup of
already dispatched effects, or behavior after an external browser handoff.
This is one browser and platform. The probe does not cover DNS, WebRTC,
WebSockets, cross-browser policy differences, browser vulnerabilities, native
bridges, process resource limits or filesystem policy. An IndexedDB open call
in the control establishes access to the API, not successful durable writes.
The Chrome flags suppress some background activity but do not enforce egress.

## Conditions for a future implementation

A supervisor must deny unapproved connections and navigations before dispatch,
including same-frame navigation, redirects, new contexts, local services and
non-HTTP channels. Enforce egress outside the child and verify both browser
and destination observations. Do not use response CORS, JavaScript wrappers,
navigation notifications or the iframe sandbox alone as the egress boundary.
Use a dedicated disposable execution context with no Studio credentials,
filesystem mounts, native bridge or privileged profile state. Prefer a design
that gives the child no general message authority. Any later host protocol
needs an explicit narrow schema, a session-bound source check and replay
rejection.

Stop must revoke session authority before initiating teardown. The supervisor
needs an independent deadline and a way to end owned execution even when the
document stops cooperating. Late callbacks must lose authority. If termination
is uncertain, keep ownership and a retry path. Confirm that a failed or
stopped launch leaves the last working preview usable. Before enabling
model-written script, independently review the implemented host enforcement
and run positive interaction plus adversarial network, resource and teardown
cases on each supported host.

## Reproduce

From the repository root, run with the installed Chrome executable:

```sh
python3 asg/tools/html_interactive_boundary_probe.py \
  --chrome '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'
```

The tool emits browser and canary observations as JSON and exits nonzero for
a failed observation. The fixture needs permission to bind ephemeral loopback
ports and launch Chrome. It creates a fresh temporary profile for each run.
